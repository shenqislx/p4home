# Phase 7C1 Product Wiring and Review Gate

> Date: 2026-08-27

> Runtime: Node v24.19.0 / pnpm 11.19.0

## Verdict

Phase 7C1 product wiring and local control/audit coding passed independent review after fixes. This closes only
the product-code gate. It does not prove a real ESP32-P4 action, real Home Assistant event, real model latency,
or long-running hardware/resource stability; those remain the next Phase 7C gate.

## Implemented boundary

- `pnpm start:voice` keeps Cat Autonomy disabled unless explicitly enabled;
- enabled mode requires Robot HA, strict local alias/domain/room mappings, a separate Device Protocol v2 listener,
  and a loopback-only bearer control token;
- Timer, configured HA aliases, P4 World changes, and body-free task completion all enter one bounded source bridge;
- the runtime activates only after P4 hello/capabilities/snapshot readiness and rejects offline events before policy
  admission or model invocation;
- policy decisions and terminal execution outcomes are separately queryable with bounded retention;
- shutdown closes ingress immediately, cancels Cat leases, drains in-flight work, and then closes device/storage state.

## Independent review and fixes

Two independent bug reviews found six initial issues and two follow-up issues. All were fixed and regression-tested:

- autonomy World completion feedback caused a second model call;
- offline P4 was reported ready and could consume model budget;
- a retained task-complete sink could start work after shutdown;
- ready same-device socket replacement retained the old session;
- unmapped HA events could consume ingress capacity;
- non-Timer terminal results were not visible to operators;
- product config accepted a wider daily-budget range than policy;
- small execution-audit capacities could turn a valid query into HTTP 500;
- signal handling briefly left autonomy active while Voice drained.
